# IIVCS Glossary

Definitions for the terms, acronyms, and external frameworks referenced across the Insheights Integrated Value Creation System.

---

## Core System and Frameworks

| Term | Definition |
|---|---|
| **IIVCS** | **Insheights Integrated Value Creation System** — the integrated system of organizational and product frameworks ([Organization Strategy Model (OSM)](README.md#osm--organization-strategy-model), [Product Transformation System (PTS)](README.md#pts--product-transformation-system), [Customer Value Delivery Model (CVDM)](README.md#cvdm--customer-value-delivery-model)) and measurement models ([Efficiency, Experience, Effectiveness (3E)](3e.md), [Adoption, Engagement, Retention (AER)](aer.md), 8 Values) through which an organization defines, builds, and delivers value. |
| **OSM** | **Organization Strategy Model** — how organizations translate strategic intent into prioritized value creation outcomes, connecting Values, Mission, and Vision through Strategic Value Creation to execution by value stream. |
| **PTS** | **Product Transformation System** — how organizations create value through the interplay of strategy, the product operating model, product management activities, and Product Mindset. |
| **CVDM** | **Customer Value Delivery Model** — how every customer/user journey step triggers the right value stage to deliver the value proposition as a realized customer outcome, with five continuous feedback loops. |
| **POM** | **Product Operating Model** — the operating model PTS stands up: four POM Enablers (Leadership; Practices & Behaviors; Organizational Architecture; Culture & Relationships) that empower persistent cross-functional teams. |
| **Product Mindset** | The operating philosophy of the IIVCS — five principles: customer obsession, outcome over output, continuous discovery, hypothesis-driven thinking, cross-functional ownership. |

## Measurement Models

| Term | Definition |
|---|---|
| **3E** | **Efficiency, Experience, Effectiveness** — the operational value measurement model, sequenced Use → Feel → Achieve, applied consistently across every architecture element. |
| **Efficiency (Use)** | Whether value is accessible without unnecessary friction, effort, cost, or complexity. The table stake; a leading, operational signal. |
| **Experience (Feel)** | Whether value is felt positively — trust, confidence, reduced anxiety. The bridge between Use and Achieve; the earliest signal of value being realized (Efficiency surfaces first, as friction in use), and attitudinal: what people report they feel or intend. What they then do is AER. |
| **Effectiveness (Achieve)** | Whether intended outcomes are achieved for customer and organization. The proof of value; a lagging, outcome signal. |
| **AER** | **Adoption, Engagement, Retention** — the behavioral measurement model that sits between 3E and the 8 Values, measuring behavioral response to value delivery across two tracks. |
| **Customer AER** | Behavioral response from the customer side — adoption, engagement, retention (or **Recommendation**) of the value offered. |
| **Organizational AER (Org AER)** | Behavioral response from the delivering organization to the operating model — adoption (the breadth of teams running its practices), engagement (review output that reaches decisions; changes teams make to the model themselves), and retention (the way of working, the people, and the knowledge that carry it persisting: practice persistence, team continuity, voluntary turnover). |
| **8 Values** | **Insheights 8 Organizational Values Measurement Model** — the eight dimensions of Organization Value: Customer, Financial, People, Operational, Market, Strategic, Innovation, Impact. |
| **Feedback System** | The two-level upstream feedback path (operational via CVDM's five loops; organizational via the 8 Values) running CVDM → PTS → OSM. |
| **Continuous feedback** | Feedback that is sought in every phase of the [product lifecycle](#key-concepts), from Discover to Support, not only at a point-in-time review. Each loop runs at its own cadence (see the [feedback loops table](feedback.md#operational-feedback--cvdm)); it does not mean every signal is read in real time. |

## Architecture Elements

The named layers 3E measures and CVDM activates, from broadest to most granular.

| Term | Definition |
|---|---|
| **Value Stream** | The chain of value stages through which the organization delivers an outcome its stakeholder values: usually a customer, sometimes an internal user. It starts when that stakeholder asks for or needs the outcome, and ends when they have it. Value streams are the common organizing spine across OSM, PTS, and CVDM. Most already exist; when a strategy needs an outcome none of them delivers, OSM may create or reshape one, and PTS builds it. |
| **Value Stage** | A step in a value stream, with a clear start and finish, that leaves its stakeholder measurably closer to the stream's outcome. When the stakeholder is a customer, each stage serves one or more customer-journey steps. |
| **Capability** | Something the organization can do, named for what it achieves, not who does it or how. Named once on the organization-wide capability map, it can enable value stages in any value stream. |
| **Capability Map** | The single, organization-wide list of the organization's capabilities. OSM holds it alongside the value-stream inventory, adopting an existing business-architecture map where the organization has one; PTS records which team owns each capability and which teams consume it; CVDM selects from it for each value stage. Capabilities sourced from a partner are on the map too, marked as partner-sourced. |
| **Process** | The repeatable sequence of activities that carries out a capability's work within a value stage. |
| **Information Concept** | A named piece of business information a value stage needs or produces, such as an application or a verification status, in the terms the business uses for it. It is defined once, has an owner, and feeds the capabilities that act on it. |
| **Product / Service** | The delivered offering through which customers access and use value. |
| **Value Proposition** | What a value stream promises to deliver to its stakeholder, realized as that stakeholder's outcome. |

## Key Concepts

| Term | Definition |
|---|---|
| **Product lifecycle** | PTS's six phases: Discover, Define, Develop, Deliver, Launch and Support. They are continuous and overlapping, and run from building a product to supporting it in use: Discover runs throughout, and Launch covers both external go-to-market and internal change adoption. |
| **Market stages** | The stages a product passes through in its market: introduction, growth, maturity and decline. |
| **Leading indicator** | A signal that surfaces before the outcome it predicts (Efficiency, Experience; AER Adoption, Engagement). Leading and lagging describe timing relative to a named outcome, not what is measured. Enables intervention before damage registers. |
| **Lagging indicator** | A signal that confirms an outcome after the fact (Effectiveness; AER Retention; most 8 Values signals). |
| **Behavioral signal** | An observed action: what customers or teams actually do (return, use, renew, refer, stay). AER's signals are behavioral. |
| **Attitudinal signal** | A reported feeling or intent: what people say they feel or would do (CSAT, CES, NPS, eNPS). 3E Experience's signals are attitudinal. |
| **Compounding** | The property that value dimensions reinforce and amplify each other over time, rather than operating independently. |
| **Elements of Value** | Bain & Company's research taxonomy — 30 B2C and 40 B2B elements of what customers value. Insheights maps all 70 to the 3E dimensions; the mapping is Insheights' own. |
| **Value priority** | A strategic objective set in OSM, stated as an outcome (not an activity or deliverable), ranked against the others, and resting on written hypotheses. |
| **Value-stream outcome** | The business intent a value stream exists to produce, defined by OSM, delivered through PTS, and evidenced by customer outcomes. It is not simply the sum of what teams deliver. |
| **Value-stream charter** | The record OSM makes when it creates or reshapes a value stream: the stakeholder, the outcome, the owner, why no existing stream delivers it, and the build capacity committed under the priority that called for it. |
| **Core team** | A persistent cross-functional team aligned to one value stream and the value stages it serves; a value stream has one or more Core teams. It owns the customer outcomes at its stages, which evidence the value-stream outcome, and delivers them end to end, without hand-offs. It owns the capabilities only its stages use and consumes the rest; when two Core teams in one stream use a capability, one owns it and the other consumes it. The value-stream owner owns the value-stream outcome. |
| **Shared team** | A persistent team that owns a capability value stages in several value streams draw on. It serves those streams' Core teams on agreed terms and is judged on their outcomes. |
| **Platform-Enabled team** | A persistent team that owns a technology capability, such as a platform, data and AI, integration or developer tooling, and offers it as a self-service internal product, so other teams consume it without hand-offs. |
| **Owned / consumed capability** | Each capability on the capability map has one owning team; every other team that draws on it consumes it. A partner-sourced capability is always consumed, with one internal team accountable for the partner: the team that would own it if it were built in-house. |
| **Diagnosis (key challenge)** | The one or two critical challenges a strategy must overcome, and why they are hard. A diagnosis names the obstacle; a context description only describes the situation. |
| **Strategic choices** | The explicit OSM decisions about where to play, where not to play, and how to win. |
| **How to win / theory of change** | Why the chosen customers will choose the organization over the alternatives, and the hard-to-copy advantage that makes this deliverable. In non-competitive contexts, the theory of change: why this approach will produce the outcome when past efforts did not. |
| **One-Page Strategy** | The OSM artifact that holds the diagnosis and the strategic choices on a single page. |
| **Priority Register** | The living OSM artifact that holds the ranked value priorities. Each entry records the outcome, target, and date; the key challenge it addresses; its key hypotheses, each with its experiment, rejection condition and status; its horizon, value stream, owner, committed resources, and measurement frame. |
| **Decision forum** | OSM's governance forum, held at the organization's planning cadence: it gives each strategic hypothesis its status, then persists, retunes, re-resources or retires each value priority, and takes executability escalations and lapsed sponsor mandates. It decides what is funded and prioritized; how the work is done is the operating-model review's. |
| **Operating-model review** | PTS's review of one value stream's way of working, held by the value-stream owner with POM Leadership at the organization's planning cadence, before each decision forum. It reads Organizational AER and PTS's health signals and changes practices, roles and team setup; anything that moves funding, priorities or the sponsor's mandate goes up to the decision forum. |
| **Strategic hypothesis** | A belief a value priority depends on, written with the experiment that tests it (or, where none is possible, a dated observation), the result that would reject it, and when it will be read. At each decision forum it is marked from its latest run: *accepted* (the run did not meet the rejection condition), *rejected* (it did), or *not yet run* (no run has reached its read date). An experiment may be run again under the same rejection condition; changing the condition makes a new hypothesis. |
| **System health indicator** | A signal that confirms a framework is working — generating executable strategy / delivering against priorities / producing customer outcomes — not merely being followed. |

## Diagram Arrow Vocabulary

Every arrow in the IIVCS diagrams carries a label from this vocabulary, and a word means the same thing in every diagram it appears in.

**Conventions**
- **Work flow** (grey arrow): a verb, read from the arrow's source to its target — *Vision **directs** Strategic Value Creation*.
- **Feedback flow** (blue arrow, italic label): the name of what flows back. OSM and CVDM number their feedback loops 1–5 as a sequence.
- **System hand-offs** (IIVCS diagram): the noun handed between frameworks — *value priorities* and *product teams* down, *value-stream outcomes*, *strategic signals* and *customer outcomes* back up.
- Words inside a box or band that state a relationship use the same vocabulary (listed under *Relationship words* below).
- **8-Values diagram:** a one-way relationship is an arrow carrying a verb (source → target); a two-way relationship has a head at each end and names what passes both ways. All its arrows are grey: they are compounding relationships between Values, not work or feedback flows. Each label summarises a row of the *Compounding Relationships* tables in [8 Values](8-values.md).

| Verb | Meaning | Where it appears (source → target) |
|---|---|---|

| **directs** | Sets the direction the target moves toward | OSM: Vision → Strategic Value Creation |

| **experienced through** | The product or service by which the customer meets the target | CVDM: Value Stage → Product/Service |
| **experiences** | Encounters directly | CVDM: Customer/User → Value Proposition |
| **feed / feeds** | Supplies what the target needs, when it needs it: the signal a measure reads, or the information a capability acts on | CVDM: Information Concept → Capability. Measurement Architecture: Customer Journey Steps → AER (customer track); Product Team & Product Operating Model → AER (organization track) |
| **flags risk** | Raises a risk signal for the target to act on | OSM: Enterprise Risk Mgmt → Governance & Measurement; → Execution & Deployment |

| **gives purpose** | Supplies the reason the target exists | OSM: Mission → Strategic Value Creation |
| **governs conduct** | Sets how the target must behave | OSM: Values → Governance & Measurement (outcomes are read against Values) |
| **guides** | Supplies the principles the target follows | OSM: Values → Strategic Value Creation |
| **informs** | Supplies evidence the target uses | OSM: Internal Context, External Context → Strategic Value Creation |
| **measured by** | Is measured by the target | Measurement Architecture: Outcomes → 3E Effectiveness (lagging); Architecture Elements → 3E (all three dimensions) |
| **operationalizes** | Makes repeatable in practice | CVDM: Process → Capability |
| **participates in** | Takes part in | CVDM: Stakeholder → Value Stage |
| **produces** | Brings about as a result | PTS: product team → Business / Customer Outcomes |
| **reaches** | Arrives at the customer, where the value is realized as an outcome | CVDM: Value → Customer/User |

| **sets** | Defines what the target must achieve | OSM: Strategic Value Creation → Governance & Measurement (*value priorities*); Governance & Measurement → Execution & Deployment (*value-stream outcomes*). PTS: Objectives by value stream → product team (*value-stream outcomes*) |
| **shapes** | Influences the form of | OSM: Stakeholder & Customer Expectations → Strategic Value Creation |

### Distinctions

- **delivers vs reaches** — a value stream *delivers* its value proposition, and a product or service *delivers* a value: the organization produces and hands over what it promised. Value then *reaches* the customer, where it is realized as an outcome. *Delivers* is the organization's act; *reaches* is the value's arrival.
- **empower vs enables** — *empower* is about people (the POM Enablers give teams the authority and means to own outcomes); *enables* is about ability (a capability makes a value stage possible; PTS supplies CVDM with teams and capabilities).
- **decides vs sets** — *decides* is making the choice (leadership); *sets* is fixing the target others then work to (value priorities, value-stream outcomes).
- **constrains vs flags risk** — *constrains* is a standing limit (risk appetite); *flags risk* is a signal raised when something needs attention.
- **Value Stage vs AER stage vs market stages** — a [Value Stage](#architecture-elements) is a step in a value stream; an AER stage is one of Adoption, Engagement and Retention, the behavioral sequence [AER](#measurement-models) reads; [market stages](#key-concepts) are the introduction, growth, maturity and decline a product passes through in its market, an outside sequence and not an IIVCS framework term.
- **value priorities vs value-stream outcomes** — value priorities are OSM's ranked, outcome-stated objectives; value-stream outcomes are the business intent each value stream must produce. Both flow down; evidence of value-stream outcomes flows back up.

## External Frameworks Referenced

Frameworks the IIVCS comparison, integration, and guide documents reference. Listed for reference; see those documents for detail.

| Term | Definition |
|---|---|
| **IR / IIRC 6 Capitals** | The Integrated Reporting framework, first issued by the International Integrated Reporting Council and now maintained by the IFRS Foundation, defining six capitals — Financial, Manufactured, Intellectual, Human, Social & Relationship, Natural. The 8 Values bridges to it for external reporting. |
| **Balanced Scorecard (BSC)** | Kaplan & Norton's four-perspective strategic measurement framework (Financial, Customer, Internal Process, Learning & Growth). |
| **ESG / GRI / SASB / TCFD / ISSB** | Environmental, Social, Governance disclosure standards and the bodies that set them (Global Reporting Initiative; Sustainability Accounting Standards Board; Task Force on Climate-related Financial Disclosures; International Sustainability Standards Board). |
| **OKRs** | Objectives & Key Results — a goal-alignment and progress-tracking system. |
| **Hoshin Kanri** | A strategy-deployment method that cascades breakthrough objectives through the organization by negotiated alignment ("catchball"), often using the X-matrix. |
| **Rumelt's strategy kernel** | From *Good Strategy / Bad Strategy*: diagnosis, guiding policy, and coherent actions. The minimum structure of a real strategy. |
| **Playing to Win** | Lafley & Martin's strategy-formulation framework of five cascading choices: winning aspiration, where to play, how to win, must-have capabilities, and management systems. |
| **Porter — competitive strategy** | Michael Porter's competitive-analysis tools (Five Forces, value chain, generic strategies) for understanding industry structure and competitive advantage. |
| **EFQM / RADAR** | EFQM Model (European Foundation for Quality Management) — an organizational assessment model asking three questions, Direction, Execution and Results, across seven criteria; RADAR (Results, Approaches, Deployment, Assessment & Refinement) is its assessment logic. |
| **TOGAF / BIZBOK / ArchiMate** | Enterprise Architecture frameworks and modeling language. |
| **SAFe** | Scaled Agile Framework — enterprise agile delivery framework. |
| **JTBD** | Jobs To Be Done — a framework for understanding the job a customer hires a product to do. |
| **Service Blueprint / Value Stream Mapping** | Service design and lean process-mapping techniques. |
| **ISO 9241-11** | International usability standard defining Effectiveness, Efficiency, Satisfaction. |
| **Google HEART** | User-centered metric categories for web products: Happiness, Engagement, Adoption, Retention, Task Success (Google, 2010). Adoption, Engagement and Retention are behaviors; in IIVCS they sit in AER. |
| **AARRR** | "Pirate Metrics" growth funnel — Acquisition, Activation, Retention, Referral, Revenue. |
| **Prosci ADKAR** | Individual change model — Awareness, Desire, Knowledge, Ability, Reinforcement. |
| **Kotter 8-Step** | Kotter's eight-step model for leading organizational change. |
| **McKinsey 7-S** | Organizational alignment model — Strategy, Structure, Systems, Staff, Skills, Style, Shared Values. |
| **Gallup Q12** | A 12-item employee engagement survey instrument. |

## Common Metrics and Acronyms

| Term | Definition |
|---|---|
| **NPS** | Net Promoter Score — stated likelihood to recommend; an attitudinal 3E Experience signal. The referral itself is recorded in Customer AER (Recommendation). |
| **Net Promoter System** | Bain & Company's management practice around NPS: an inner loop in which frontline teams follow up each customer's feedback, and an outer loop that takes issues beyond frontline control to structural fixes. Not the score itself. |
| **eNPS** | Employee Net Promoter Score — teams' stated likelihood to recommend the organization as a place to work; an attitudinal 3E Experience signal (internal), which People Value reads from. |
| **CSAT** | Customer Satisfaction Score — satisfaction with a specific interaction. |
| **CES** | Customer Effort Score — the effort a customer reports in completing a task; an attitudinal 3E Experience signal of perceived effort. Observed friction is read in Efficiency. |
| **CLV / LTV** | Customer Lifetime Value — total value a customer generates over the relationship. |
| **OEE** | Overall Equipment Effectiveness — a manufacturing performance measure. |
| **GTM** | Go-To-Market — external launch motion (awareness, acquisition, channel activation). |
| **B2B / B2C** | Business-to-business / business-to-consumer. |
| **ERM** | Enterprise Risk Management. |
| **ITIL** | IT service management framework. |
| **IP / R&D** | Intellectual Property / Research & Development. |
