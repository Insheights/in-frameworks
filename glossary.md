# IIVCS Glossary

Definitions for the terms, acronyms, and external frameworks referenced across the Insheights Integrated Value Creation System.

---

## Core System and Frameworks

| Term | Definition |
|---|---|
| **IIVCS** | **Insheights Integrated Value Creation System** — the integrated system of organizational and product frameworks (OSM, PTS, CVDM) and measurement models (3E, AER, 8 Values) through which an organization defines, builds, and delivers value. |
| **OSM** | **Organization Strategy Model** — how organizations translate strategic intent into prioritized value creation outcomes, connecting Values, Mission, and Vision through Strategic Value Creation to execution by value stream. |
| **PTS** | **Product Transformation System** — how organizations create value through the interplay of strategy, the product operating model, product management activities, and Product Mindset, enabled by AI. |
| **CVDM** | **Customer Value Delivery Model** — how every customer/user journey step triggers the right value stream stage to deliver the value proposition as a realized customer outcome, with five continuous feedback loops. |
| **POM** | **Product Operating Model** — the operating model PTS stands up: four POM Enablers (Leadership; Practices & Behaviors; Organizational Architecture; Culture & Relationships) that empower persistent cross-functional teams. |
| **Product Mindset** | The operating philosophy of the IIVCS — five principles: customer obsession, outcome over output, continuous discovery, hypothesis-driven thinking, cross-functional ownership. |

## Measurement Models

| Term | Definition |
|---|---|
| **3E** | **Efficiency, Experience, Effectiveness** — the operational value measurement model, sequenced Use → Feel → Achieve, applied consistently across every architecture element. |
| **Efficiency (Use)** | Whether value is accessible without unnecessary friction, effort, cost, or complexity. The table stake; a leading, operational signal. |
| **Experience (Feel)** | Whether value is felt positively — trust, confidence, reduced anxiety. The bridge between Use and Achieve; the earliest leading behavioral signal. |
| **Effectiveness (Achieve)** | Whether intended outcomes are achieved for customer and organization. The proof of value; a lagging, outcome signal. |
| **AER** | **Adoption, Engagement, Retention** — the behavioral measurement model that sits between 3E and the 8 Values, measuring behavioral response to value delivery across two tracks. |
| **Customer AER** | Behavioral response from the customer side — adoption, engagement, retention (or **Recommendation**) of the value offered. |
| **Organizational AER (Org AER)** | Behavioral response from the delivering organization — adoption of the operating model, engagement with purpose and work, retention of talent and institutional knowledge. |
| **8 Values** | **Insheights 8 Organizational Values Measurement Model** — the eight dimensions of Organization Value: Customer, Financial, People, Operational, Market, Strategic, Innovation, Impact. |
| **Feedback System** | The two-level upstream feedback path (operational via CVDM's five loops; organizational via the 8 Values) running CVDM → PTS → OSM. |

## Architecture Elements

The named layers 3E measures and CVDM activates, from broadest to most granular.

| Term | Definition |
|---|---|
| **Value Stream** | The pre-existing business workflows and capabilities through which value is created and delivered — the common organizing spine across OSM, PTS, and CVDM. |
| **Value Stage** | A stage within a value stream, triggered by a customer journey step, that contributes to the customer outcome. |
| **Capability** | An organizational ability that activates within a value stage to contribute to its outcome. |
| **Process** | The repeatable execution that produces a consistent outcome within a capability or stage. |
| **Product / Service** | The delivered offering through which customers access and use value. |
| **Value Proposition** | What a value stream promises to deliver to the customer, realized as a customer outcome. |

## Key Concepts

| Term | Definition |
|---|---|
| **Leading indicator** | A signal that surfaces before outcomes materialize (Efficiency, Experience; AER Adoption, Engagement). Enables intervention before damage registers. |
| **Lagging indicator** | A signal that confirms an outcome after the fact (Effectiveness; AER Retention; most 8 Values signals). |
| **Compounding** | The property that value dimensions reinforce and amplify each other over time, rather than operating independently. |
| **Elements of Value** | Bain & Company's research taxonomy — 30 B2C and 40 B2B elements of what customers value. 3E maps to all 70. |
| **Value priority** | A strategic objective set in OSM, stated as an outcome (not an activity or deliverable), ranked against the others, and resting on written assumptions. |
| **Value-stream outcome** | The business intent a value stream exists to produce, defined by OSM, delivered through PTS, and evidenced by customer outcomes. It is not simply the sum of what teams deliver. |
| **Diagnosis (crux)** | The one or two critical challenges a strategy must overcome, and why they are hard. A diagnosis names the obstacle; a context description only describes the situation. |
| **Strategic choices** | The explicit OSM decisions about where to play, where not to play, and how to win. |
| **How to win / theory of change** | Why the chosen customers will choose the organization over the alternatives, and the hard-to-copy advantage that makes this deliverable. In non-competitive contexts, the theory of change: why this approach will produce the outcome when past efforts did not. |
| **Strategy Kernel** | The one-page OSM artifact that holds the diagnosis and the strategic choices. |
| **Priority Register** | The living OSM artifact that holds the ranked value priorities. Each entry records the outcome, target, and date; the crux it addresses; its key assumptions and the tests that would refute them; its horizon, value stream, owner, committed resources, and measurement frame. |
| **Strategic assumption** | A belief a value priority depends on, written with the evidence that would refute it and when that evidence will be checked. OSM's feedback loop tests it. |
| **System health indicator** | A signal that confirms a framework is working — generating executable strategy / delivering against priorities / producing customer outcomes — not merely being followed. |

## Diagram Arrow Vocabulary

Every arrow in the IIVCS diagrams carries a label from this vocabulary, and a word means the same thing in every diagram it appears in.

**Conventions**
- **Work flow** (grey arrow): a verb, read from the arrow's source to its target — *Vision **directs** Strategic Value Creation*.
- **Feedback flow** (blue arrow, italic label): the name of what flows back. OSM and CVDM number their feedback loops 1–5 as a sequence.
- **System hand-offs** (IIVCS diagram): the noun handed between frameworks — *value priorities* and *product teams* down, *value-stream outcomes*, *strategic signals* and *customer outcome* back up.
- Words inside a box or band that state a relationship use the same vocabulary (listed under *Relationship words* below).
- **8-Values diagram:** most of its relationships run both ways, so each arrow carries a number (1–16) keyed to the *Compounding Relationships* tables in [8 Values](8-values.md), where both directions are written out. Blue marks the two one-way relationships typed *Feedback*.

### Work-flow verbs

| Verb | Meaning | Where it appears (source → target) |
|---|---|---|
| **constrains** | Sets limits the target must stay within | OSM: Enterprise Risk Mgmt → Strategic Value Creation (risk appetite) |
| **decides** | Makes the choice | OSM: Leadership Direction → Strategic Value Creation |
| **delivers** | Produces and hands over the value that was promised | CVDM: Value Stream → Value Proposition; Product/Service → Value |
| **drives** | Causes the target to move; here, 3E performance produces the AER response, and AER behaviour produces the 8 Values | Measurement Architecture: 3E → Customer AER, Organization AER; Customer AER, Organization AER → 8 Values (*drive*) |
| **directs** | Sets the direction the target moves toward | OSM: Vision → Strategic Value Creation |
| **empower** | Equips and authorizes people to own and act | PTS: POM Enablers → product team |
| **enables** | Supplies the ability the target needs to function | CVDM: Capability → Value Stage. Also the PTS → CVDM relation in [Positioning](positioning.md) |
| **experienced through** | The product or service by which the customer meets the target | CVDM: Value Stage → Product/Service |
| **experiences** | Encounters directly | CVDM: Customer/User → Value Proposition |
| **feed** | Supply the behavioural signal the target measures | Measurement Architecture: Customer Journey Steps → Customer AER; Product Team & Product Operating Model → Organization AER |
| **flags risk** | Raises a risk signal for the target to act on | OSM: Enterprise Risk Mgmt → Governance & Measurement; → Execution & Deployment |
| **fulfills** | Meets a promise | CVDM: Value Stage → Value |
| **funds** | Commits budget and capacity | OSM: Governance & Measurement → Execution & Deployment. PTS: Objectives by value stream → product team |
| **gives purpose** | Supplies the reason the target exists | OSM: Mission → Strategic Value Creation |
| **governs conduct** | Sets how the target must behave | OSM: Values → Governance & Measurement (outcomes are read against Values) |
| **guides** | Supplies the principles the target follows | OSM: Values → Strategic Value Creation |
| **informs** | Supplies evidence the target uses | OSM: Internal Context, External Context → Strategic Value Creation |
| **measured by** | Has its delivery performance measured by the target | Measurement Architecture: Architecture Elements → 3E |
| **operationalizes** | Makes repeatable in practice | CVDM: Process → Capability |
| **participates in** | Takes part in | CVDM: Stakeholder → Value Stage |
| **produces** | Brings about as a result | PTS: product team → Business / Customer Outcomes |
| **reaches** | Arrives at the customer, where the value is realized as an outcome | CVDM: Value → Customer/User |
| **re-prioritizes, re-allocates** | Changes the rank order, and moves resources, in response to results | PTS: Objectives by value stream → product team |
| **sets** | Defines what the target must achieve | OSM: Strategic Value Creation → Governance & Measurement (*value priorities*); Governance & Measurement → Execution & Deployment (*value-stream outcomes*). PTS: Objectives by value stream → product team (*value-stream outcomes*) |
| **shapes** | Influences the form of | OSM: Stakeholder & Customer Expectations → Strategic Value Creation |
| **triggers** | Starts | CVDM: Journey Step → Value Stage |
| **undergoes** | Goes through | CVDM: Customer/User → Customer Journey |

### Distinctions

- **delivers vs reaches** — a value stream *delivers* its value proposition, and a product or service *delivers* a value: the organization produces and hands over what it promised. Value then *reaches* the customer, where it is realized as an outcome. *Delivers* is the organization's act; *reaches* is the value's arrival.
- **empower vs enables** — *empower* is about people (the POM Enablers give teams the authority and means to own outcomes); *enables* is about ability (a capability makes a value stage possible; PTS supplies CVDM with teams and capabilities).
- **decides vs sets** — *decides* is making the choice (leadership); *sets* is fixing the target others then work to (value priorities, value-stream outcomes).
- **constrains vs flags risk** — *constrains* is a standing limit (risk appetite); *flags risk* is a signal raised when something needs attention.
- **value priorities vs value-stream outcomes** — value priorities are OSM's ranked, outcome-stated objectives; value-stream outcomes are the business intent each value stream must produce. Both flow down; evidence of value-stream outcomes flows back up.

## External Frameworks Referenced

Frameworks the IIVCS comparison, integration, and guide documents reference. Listed for reference; see those documents for detail.

| Term | Definition |
|---|---|
| **IR / IIRC 6 Capitals** | International Integrated Reporting Council framework defining six capitals — Financial, Manufactured, Intellectual, Human, Social & Relationship, Natural. The 8 Values bridges to it for external reporting. |
| **Balanced Scorecard (BSC)** | Kaplan & Norton's four-perspective strategic measurement framework (Financial, Customer, Internal Process, Learning & Growth). |
| **ESG / GRI / SASB / TCFD / ISSB** | Environmental, Social, Governance disclosure standards and the bodies that set them (Global Reporting Initiative; Sustainability Accounting Standards Board; Task Force on Climate-related Financial Disclosures; International Sustainability Standards Board). |
| **OKRs** | Objectives & Key Results — a goal-alignment and progress-tracking system. |
| **Hoshin Kanri** | A strategy-deployment method that cascades breakthrough objectives through the organization by negotiated alignment ("catchball"), often using the X-matrix. |
| **Rumelt's strategy kernel** | From *Good Strategy / Bad Strategy*: diagnosis, guiding policy, and coherent actions. The minimum structure of a real strategy. |
| **Playing to Win** | Lafley & Martin's strategy-formulation framework of five cascading choices: winning aspiration, where to play, how to win, must-have capabilities, and management systems. |
| **Porter — competitive strategy** | Michael Porter's competitive-analysis tools (Five Forces, value chain, generic strategies) for understanding industry structure and competitive advantage. |
| **EFQM / RADAR** | EFQM Excellence Model — European organizational quality framework; RADAR (Results, Approaches, Deployment, Assessment & Refinement) is its scoring method. |
| **TOGAF / BIZBOK / ArchiMate** | Enterprise Architecture frameworks and modeling language. |
| **SAFe** | Scaled Agile Framework — enterprise agile delivery framework. |
| **JTBD** | Jobs To Be Done — a framework for understanding the job a customer hires a product to do. |
| **Service Blueprint / Value Stream Mapping** | Service design and lean process-mapping techniques. |
| **ISO 9241-11** | International usability standard defining Effectiveness, Efficiency, Satisfaction. |
| **Google HEART** | Product UX measurement framework — Happiness, Engagement, Adoption, Retention, Task Success. |
| **AARRR** | "Pirate Metrics" growth funnel — Acquisition, Activation, Retention, Referral, Revenue. |
| **Prosci ADKAR** | Individual change model — Awareness, Desire, Knowledge, Ability, Reinforcement. |
| **Kotter 8-Step** | Kotter's eight-step model for leading organizational change. |
| **McKinsey 7-S** | Organizational alignment model — Strategy, Structure, Systems, Staff, Skills, Style, Shared Values. |
| **Gallup Q12** | A 12-item employee engagement survey instrument. |
