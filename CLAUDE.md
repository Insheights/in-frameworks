# Working rules — in-frameworks

The Insheights Integrated Value Creation System (IIVCS): OSM, PTS, CVDM, and the 3E → AER → 8 Values measurement architecture.

## This repo is public

Everything committed here, including this file, is readable by anyone.

- No client or prospect names, no internal strategy, no pricing, no unreleased plans, no local paths or account details.
- The Detailed Assessment instrument is private and is never copied here. This repo carries only the published methodology: the Adoption Sequencing & Maturity Model and the Quick Self-Assessment.

## Direction comes from in-scope

What this repo covers, in what order, and how it is reviewed is decided in Insheights' private `in-scope` repo, alongside this checkout at `../in-scope`. Before changing anything beyond a typo or a broken link:

1. Read `../in-scope/CLAUDE.md` and `../in-scope/frameworks/direction.md`.
2. If the change settles an open question, it is reviewed and decided there first.
3. Make the change on a branch (never `master`) and open a PR. The owner merges.

If `../in-scope` is not present, keep to edits the owner asked for in that session.

## Writing rules

- **Canonical naming.** Use each term exactly as in `glossary.md`. IIVCS is a *system* of frameworks, not a single framework.
- **One fact, one home.** Link to a definition; do not restate it.
- **Acronyms and arrows.** Spell out every acronym at its first use on each page. Diagram arrows follow the glossary's [Diagram Arrow Vocabulary](glossary.md#diagram-arrow-vocabulary).
- **Drafts stay marked.** A document marked "needs review" in `README.md` keeps that label until it is reviewed.
- **Keep the system coherent.** A change to one framework or measurement model is checked against the others it hands off to, and against `README.md` and `glossary.md`.
- **The Quick Self-Assessment's connected-link scoring** mirrors the connected components of the detailed instrument. A change to it needs the owner's sign-off.
